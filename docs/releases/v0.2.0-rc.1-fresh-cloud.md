# Fresh Cloud installation — v0.2.0-rc.1

This path prepares a new Raspberry Pi 4 directly for Button Box Cloud.
It does not need a separate WhatsApp number for the box, a wacli installation,
or a standalone WhatsApp pairing step. The owner uses the Cloud service's
WhatsApp account and dashboard.

This is the first additional-unit test of the new installer. Its isolated
software checks and the earlier runtime evidence do not prove installation,
physical controls or household acceptance on your unit.

## Prepare the new unit

1. Confirm the exact unit, final hardware and a new dedicated microSD card.
   Erasing a card requires explicit confirmation of that disk. Keep any old
   household card intact.
2. Install Raspberry Pi OS Lite 64-bit based on Debian 13. Set a unique hostname,
   a non-root administrator, SSH public-key access, correct network country,
   and a temporary internet connection. Do not publish passwords or keys.
3. Verify the SSH host key and physical unit identity. Test the microphone,
   speaker, button, LED and fitted NFC reader before application installation.
   Keep each unit's results separate.
4. Select this exact prerelease and its checksums. Confirm that the intended
   service permits the new unit and test owner. A configured server URL alone
   does not grant access, send authority or a subscription.

Do not copy another unit's configuration, Cloud credentials, device identity,
pairing, household data, SD image or pre-existing application state.

## Verify the release

Keep the supplied archive, `release-manifest.json`, `installed-files.sha256`
and `SHA256SUMS` together. Verify the checksums before extraction:

```sh
shasum -a 256 -c SHA256SUMS &&
mkdir button-box-v0.2.0-rc.1 &&
tar -xzf button-box-v0.2.0-rc.1-device-source.tar.gz \
  -C button-box-v0.2.0-rc.1 &&
cd button-box-v0.2.0-rc.1
```

The archive includes the exact release manifest. Use that extracted source
throughout installation. Do not replace it with a newer checkout.

## Install directly in Cloud mode

Replace `administrator@new-box.local` with the verified new unit's SSH target:

```sh
./scripts/provision.sh --transport cloud administrator@new-box.local
```

The explicit Cloud path refuses an existing Button Box installation or private
state before changing services or installing packages. It writes the initial
Cloud configuration, skips the wacli installer, and keeps onboarding incomplete.
It does not create a provider subscription, claim the unit, or send a message.

A successful pinned installation records its exact version, commit and manifest
hash in `/opt/messagebox/release.json`. Verify this record and every installed
file against the supplied manifest before continuing. Keep the installer result
private; never publish runtime configuration or generated onboarding secrets.

If installation fails, preserve its result and inspect the unit. Do not rerun
full setup over a partial installation or bypass the fresh-install guard. Use a
reviewed recovery procedure, or reimage only an explicitly approved disposable
card after preserving any needed evidence. Existing household installations
use the bounded update guide instead.

## Start Cloud onboarding

On the new unit, use the existing Wi-Fi onboarding controls:

```sh
sudo messagebox-init-wifi-onboarding &&
sudo messageboxctl reset-wifi
```

Store the generated hotspot credentials privately and prepare the unit's setup
insert. Connect the box to its intended home Wi-Fi through the normal portal.
Open **Connect your box to WhatsApp**, follow the Cloud link or QR code, and
complete the actual button confirmation on that unit. The Cloud service and
local completion state must agree before runtime starts.

Do not use `messagebox-dev-onboard`, standalone contact discovery, or
`enter-cloud-claim` as a substitute for this fresh Cloud path. Do not invent
an onboarding completion marker or copy another unit's successful claim.

Manage the owner account, people, default recipient, settings and NFC routes
through the Cloud dashboard. Complete any subscription step through normal
Checkout only with the account owner's permission. Test-service restrictions
and available setup access must be verified for the intended unit.

## Accept each unit separately

Record artifact and service versions, installed hashes, actual audio devices,
selected Cloud mode and service health. Verify real Wi-Fi setup and recovery,
claim, owner visibility and intended recipient routing. Then test one authorized
incoming voice message, physical playback, recording/review/send, and actual
receipt at the correct counterpart. Check fitted NFC cards, settings persistence,
and recovery after a real cold power cycle.

Keep simulated-input checks separate from physical button and reader evidence.
Keep the accepted ringtone limitation and untested outage/retention/window
assertions visible. Do not repeat the entire development campaign merely because
this is another unit; repeat checks affected by its hardware, configuration or
installer.

A successful installer is not a shipment decision. Keep factory and household
readiness separate. If a factory test account claims the box, resolve ownership
through an explicitly authorized supported handoff before delivery. Local Wi-Fi
reset does not remove Cloud ownership.
