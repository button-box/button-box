# Update an existing unit to v0.2.0-rc.1

Use this procedure only for an identified, authorized Raspberry Pi 4 test unit
with an existing Button Box installation. It installs application files; it
does not install operating-system dependencies or change the selected transport.
Do not run full provisioning or setup over a household installation.

## Before the update

1. Confirm the unit identity, SSH host key, 64-bit Raspberry Pi OS installation,
   current release, connection mode and required service accounts/groups.
2. Check the existing Python, GPIO, ALSA, FFmpeg, Gunicorn and NFC dependencies,
   detected audio configuration, free space, and onboarding services. Missing
   prerequisites require a reviewed preparation step before the update.
3. Record settings, recipients, NFC mappings, queues, recordings, identity,
   pairing and active/enabled services. Preserve a consistent private backup
   on the unit and a verified private copy on the operator's computer. Include
   actual configured paths, not only the default directories.
4. For Cloud mode, verify the compatible service and account-bound heartbeat.
   Verify `/var/lib/messagebox-cloud` exists with owner
   `messagebox:messagebox-settings` and mode `2770`. If it is absent, create it
   only after the baseline backup. Do not replace an unexpected path or repair
   unexplained ownership without checking it.
5. Keep pending recordings in place. Older unbound Cloud work is preserved for
   private recovery and must not be relabeled or resent under another account.

The bounded updater's program backup does not replace this private-state backup.

## Verify and stage

Put the release assets together on the Pi and verify their checksums:

```sh
sha256sum -c SHA256SUMS
```

Use a new staging directory. The archive has no containing directory and includes
`release-manifest.json` at its root. Do not overlay a previous attempt.

```sh
sha256sum -c SHA256SUMS &&
sudo install -d -o root -g root -m 0700 /var/lib/button-box-update &&
sudo mkdir -m 0700 /var/lib/button-box-update/v0.2.0-rc.1 &&
sudo tar --extract --gzip --no-same-owner \
  --file button-box-v0.2.0-rc.1-device-source.tar.gz \
  --directory /var/lib/button-box-update/v0.2.0-rc.1
```

All staged files and directories must be root-owned and not writable by other
users. The mode generator must retain its executable mode. Compare the embedded
manifest with the separately supplied manifest before applying.

## Apply and verify

Choose a new backup path for this attempt. Do not reuse the example path if it
already exists.

```sh
sudo python3 /var/lib/button-box-update/v0.2.0-rc.1/scripts/install/bounded_update.py apply \
  --source-root /var/lib/button-box-update/v0.2.0-rc.1 \
  --manifest /var/lib/button-box-update/v0.2.0-rc.1/release-manifest.json \
  --backup-dir /var/backups/button-box/v0.2.0-rc.1-before-update &&
sudo sha256sum -c installed-files.sha256 &&
sudo cat /opt/messagebox/release.json
```

Match version, commit and manifest hash to the release assets. Compare service
state and every protected pre-existing item with the baseline. Check the local
dashboard and intended connection mode before sending any test message.

An already connected Cloud box keeps its Cloud identity. An existing standalone
box keeps its pairing and wacli mode. Neither case needs a new claim merely
because its application code was updated.

For a separately authorized configured Business-to-Cloud transition, follow
[Cloud runtime](../cloud-runtime.md). The successful transition changes private
configuration outside the bounded updater transaction. Do not use this route
as an undocumented wacli conversion or fresh-card installer.

## Recover

If the updater fails, let its automatic rollback finish and inspect its result.
Preserve its staging and backup directories. Do not retry an uncertain update.

Before rollback, confirm that the previous Pi runtime is compatible with the
current Cloud account and transport guards. The updater immediately restores
recorded active services. If the previous runtime is incompatible, do not run
the command below; use a reviewed recovery plan that keeps outbound work stopped.

For a deliberate program rollback to a compatible runtime after reconciliation:

```sh
sudo python3 /var/lib/button-box-update/v0.2.0-rc.1/scripts/install/bounded_update.py rollback \
  --backup-dir /var/backups/button-box/v0.2.0-rc.1-before-update
```

Rollback restores program files and recorded service state. It does not undo
Cloud ownership, restore household data or reverse a later transport change.
Do not restore an older full-data backup over new messages or configuration.

An earlier Pi or Cloud version might not implement account binding. Stop
outbound processing before reverting an incompatible service; retain the
account guard and resume only with a compatible pair. Keep pending work intact.

After recovery, verify software identity, service state, transport, household
preservation and the target unit's relevant acceptance checks again.
