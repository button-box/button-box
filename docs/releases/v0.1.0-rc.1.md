# v0.1.0-rc.1 — working development baseline

This first prerelease consolidates the software installed on the reference
development box on 15 September 2026. It is a source release, not a bootable SD
image, factory-sealed appliance, or per-unit delivery certificate.

## Included behavior

- Retry-safe onboarding recipient selection and rejection of the linked box's
  own account as a recipient; default changes through the recipient manager.
- Wi-Fi proof consistency and hostname discovery at onboarding completion.
- Pairing-store preflight and read-only polling before WhatsApp linking.
- Visible NFC pairing progress/cancellation and confirmed completion receipts.
- The same 400 ms acknowledgement for physical button presses and NFC scans.
- The deployed original 1.25-second successful-send swoosh. It means accepted
  for sending, not recipient-phone delivery or listening.
- Setup Activity, inline recipient addition and navigation refresh after setup.
- Deliberate early approval during review of the user's own recording.
- Boot-time USB audio detection, recovered from the installed helper and service
  definitions and now included in the installer.

## Install and verify

Use the tagged source, not an arbitrary branch tip:

```sh
git clone --branch v0.1.0-rc.1 --depth 1 https://github.com/button-box/button-box.git
cd button-box
make check
```

Follow [installation](../installation.md) for a fresh supported Pi 4 / 64-bit
Debian 13 card. Connect the microphone and USB speaker first. The installer
downloads the pinned wacli 0.17.1 and NFC dependencies; OS package versions can
vary. Existing-device installation requires stopping the box as documented;
do not reset Wi-Fi or relink WhatsApp merely to update software.

Release assets include a source archive, checksums, and an installed-code
manifest. Verify the archive before extraction and compare the manifest on the
device. A version marker alone does not prove installed-file equality. Personal
configuration, contacts, NFC mappings, messages, credentials, and recordings
are never part of the release.

From a clean tagged clone, regenerate the program-file manifest:

```sh
python3 scripts/dev/release-manifest.py > manifest.json
python3 scripts/dev/release-manifest.py --format sha256sum > installed-files.sha256
ssh admin@button-box-NNN.local 'sha256sum --check --strict' < installed-files.sha256
```

All listed files must pass before claiming installed-code equality. This checks
70 program/service/prompt files, not OS packages, generated ringtones, private
settings, or actual hardware behavior. The source archive does not contain Git
metadata; use the attached manifest for an archive installation.

## Verification boundaries and known limitations

- Combined Python/JavaScript tests, syntax, lint and secret scanning are
  software evidence. See the GitHub Release for the final counts and exact SHA.
- Reference-box installed code, audio helper and service definitions are
  compared by hash. The prior SOURCE_COMMIT marker was stale and was not used
  as proof of the running build.
- Fresh-card installation, power-loss recovery, physical USB-port swaps and
  complete per-unit acceptance remain separate gates unless explicitly
  recorded in the release's evidence. Existing guided-prompt licensing is in
  `sounds/guided-reply/LICENSE.md`; the new swoosh uses the source license.
- Ringtone previews do not yet switch immediately to the latest selection.
- Recipient-name editing, friendlier listened-announcement controls, MIDI
  upload/discovery, and alternative swoosh auditions are excluded.
- The dashboard is household-network-only and has no login. Do not expose it
  publicly. This prerelease does not certify hardware or regulatory safety.

Promote a later stable tag only after the required real-device checks pass;
do not move or overwrite an existing tag.
