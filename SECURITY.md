# Security policy

## Supported versions

There is no supported public release yet. Security fixes are evaluated against
the latest candidate.

## Reporting a vulnerability

Do not open a public issue containing exploit details, credentials, phone
numbers, authentication data, message content, or device state. Once the
private GitHub candidate exists, use GitHub private vulnerability reporting.
If that channel is unavailable, contact the maintainer privately through the
GitHub account that owns the repository and disclose only enough information to
establish a secure follow-up channel.

The public repository must not launch until private vulnerability reporting is
enabled and tested.
